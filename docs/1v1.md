# Fraud Arena 1v1

Status: design as built on `feat/1v1-runner`, 2026-11-22. Replaces the v0 multiplayer game (design doc 20 §8 in
Runmere) as the first benchmark. An earlier version of this doc proposed the small `payments-ato-mini` world and
mini-SWE-agent players; both were dropped (see "What changed").

## Why

The v0 game ran four defenders and up to four rings at once, as Claude Code and Codex sessions in a shared EC2
sandbox, ranked by Nash averaging over teams. It needed unmerged engine PRs and the 2026-11-16 review found that
players could read each other's files and see each other's model credentials.

1v1 keeps the core question: can an agent defend a bank against an agent that adapts? It drops everything else.

## The game

**One defender at Brindlemark Bank against one fraud ring, on Runmere's Fraud World.** Every other institution runs
its built-in rules; every customer, merchant and mule follows the world's behaviour.

- **World:** `worlds/fraud-world-arena.yaml`, a copy of Fraud World (Runmere `feat/ring-plan-menu`, PR #74) with
  independent fraudsters off (`fraud_density` 0): all fraud is the ring's. The ring is presented to the attacker as
  one ring with ten crews (the world's ten rings).
- **History:** a 30-day warm-up with the bank's built-in rules. The bank's tables and case log from it are the
  defender's starting data.
- **Match:** 4 weekly rounds (default). From the checkpoint on, the crews work at `intensity` times their usual
  volume (default 3) and aim at Brindlemark wherever their schemes allow. History stays at normal volume; the extra
  fraud is only in the live match.
- **Turns:** before each week, both players take one turn (in parallel) to study their data and submit a policy. The
  week then plays out under both policies. A match is 8 agent turns.
- **Opponent:** a model under test always plays against a fixed opponent: Claude Opus. No round-robin table.

### Defender

- **Decisions:** all of Brindlemark's automated decisions (card authorization, login check, account and business
  opening review, payment and ACH holds, ACH push, wires, transaction monitoring). Decisions it writes no rules for
  keep the bank's built-in rules.
- **Policy:** a Runmere deployment (SPEC §8.8): ordered rules per decision over the decision's observed features,
  optional scoring models (logistic, linear, gradient-boosted trees), and optional Grayson questions whose answers
  rules read as `outside.<question>.<option>`. Written as JSON or YAML. No player code runs in the engine.
- **Sees:** the bank's observed tables, and `cases_<decision>` tables: every case the bank decided, with its observed
  features (including memos, notes and payee names), the action taken, and `fraud_known`: fraud the bank has
  discovered, or its victim has reported (80% of fraud, 2-10 days after it becomes knowable). Never truth.
- **Tools (`arena` CLI):** `status`, `brief`, `tables`, `query` (DuckDB), `rule list/add/remove`, `policy
  help/show/set`, `fit logistic|trees` (trains on the case tables with a time split, reports AUC and top-k cutoffs,
  `--save` adds the model to the policy), `grayson` (asks Grayson a question about rows of a table, within a
  per-turn budget), `note/notes`.
- **Rollback:** if a policy stops the engine mid-week (e.g. a rule orders a missing feature), the week replays with
  the previous policy and the defender is told why.

### Attacker

- **Policy:** a plan over the ring plan menu (SPEC §8.9 interventions on ring attributes): per crew or for all,
  volume, scheme weights (22 schemes), quiet periods, timing, where to attack, institution shares, devices, network
  exits, identities, mule recruiting.
- **Budget:** total volume across crews ≤ 12, total scheme emphasis ≤ 26; an over-budget plan is rejected and last
  week's plan stays.
- **Sees:** only its own results: what each crew took from each institution each week, and the schemes it has run.
- **Writes no fraud content.** It picks from the world's menu.

### Scoring (counterfactual, per week)

Each week four runs advance from the same week-start state:

| Run | Defense | Attack |
|---|---|---|
| candidate | defender's policy | attacker's plan |
| no-defense | built-in rules | attacker's plan |
| no-attack | defender's policy | scripted crews |
| reference | built-in rules | scripted crews (context only) |

- **Defender score:** losses prevented at Brindlemark (no-defense − candidate), minus added friction on good
  customers (declines $3 + 10%, step-ups $0.50, holds $2, reviews $15, alerts $8, blocks $25, closures $200).
- **Attacker score:** what the ring takes from Brindlemark (losses + 10% of mule pass-through) in candidate minus
  no-attack. Money taken elsewhere doesn't score.

Each side is judged on its own choices: a harder attack doesn't lower the defender's score, a better defense
doesn't lower the attacker's. (The first pilots scored both against one reference run, which blamed the defender
for the attacker's escalation.) Built-in vs built-in scores exactly 0 on both sides.

## Harness

- **Players are Claude Code headless sessions** (`claude -p`) on the match machine, restricted to their own `arena`
  command (`Bash(arena:*)`) plus writing `drafts/**`; no MCP servers, no user settings, no saved session. The Grayson
  key never enters a player's environment; only the harness-side `arena grayson` reads it.
- **Same prompt template for both roles**, apart from the role brief. Per-turn cap: 25 commands.
- Every turn's transcript, cost and policy is logged under `runs/<match>/`.

## What changed from the first proposal

- Fraud World instead of `payments-ato-mini`: the small world was degenerate (losses invisible to the defender).
- Claude Code players instead of mini-SWE-agent over OpenRouter, while the harness is unfinished.
- One ring (ten crews) instead of a single ATO fraudster; independent fraudsters off.
- Fixed Opus opponent instead of a full table.
- Models and Grayson are in (they were out of v1).

## Open questions

- Is 4 weeks long enough for the attacker to probe and the defender to respond more than once?
- Does the attacker need tactical knobs (disguise, amounts) beyond the strategic plan menu?
- Public submission repo (`fraud-arena-bench`): a holdout seed set for ranked results.
