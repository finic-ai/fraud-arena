# Fraud Arena

Fraud Arena is a public benchmark, by [Finic](https://finic.ai), of how well AI models do the work of a bank's fraud
team: triaging alerts, investigating incidents, and defending a bank against an attacker that adapts. It is open in
the style of tau-bench and FrontierSWE: the tasks, the case inputs, the scoring code and example traces are public,
and the leaderboard is at **[fraudarena.com](https://fraudarena.com)**.

Every task takes place in **Fraud World**, a simulated economy with two banks, a credit union, a crypto exchange, a
brokerage, a payroll company, employers, merchants and their customers, plus independent fraudsters and ten fraud-ring
crews running 22 schemes. The world is generated by Runmere, Finic's simulation engine, and is published on Runmere's
hub: [Fraud World](https://runmere.finic.ai/public/worlds/wld_01m7gjgv6z5syh222t2g0qsyse). Every player sits at the
same institution, Brindlemark Bank, and sees only what the bank would see. Answers are graded against the simulator's
ground truth, so every label is exact.

## The three boards

| Board | What the model does | Ranked by |
|---|---|---|
| **Alert triage** | Reads one alert's case packet (the alert, the customer's profile and activity as of the alert, who shares the customer's devices, IPs and payees) and answers three questions with probabilities: is it fraud, what kind, and is the customer a perpetrator, victim, mule or legitimate. One call per alert, no tools, so decision models and general LLMs compete on the same footing. | PR-AUC on the fraud question, weighted to a 10% alert fraud rate (a realistic queue); ROC-AUC, log loss, Brier, precision at 80% recall, fraud type and role accuracy are reported alongside. |
| **Incident investigation** | Starts from an anomaly and a few seed customers, queries the bank's case file through a read-only command line in a sandbox, decides whether it is a real incident or a benign cluster, and finds every customer involved with their role. | mean@3 over cases (three independent trials each), with worst@3 / best@3, pass^3 on the verdict and a 95% bootstrap interval. |
| **1v1 defense** | Runs Brindlemark's fraud team for four weekly turns against a fraud syndicate played by Claude Opus. Each week the defender writes rules, trains scoring models, keeps lists and spends a limited review budget; the attacker re-plans its crews each week. | Share of attack losses prevented, net of the friction caused to good customers, against a replay of the same week with the bank's built-in rules. |

**Models.** Claude Opus 5.5, Sonnet 5.5 and Haiku 5.5; GPT-5.6 Sol, Terra and Luna; Inkling 2 Mini and Small; Mistral
Large 4; DeepSeek V4.1 Flash; GLM 5.3. The alert triage board also includes two decision models, Finic's Grayson and
TypeSafe's Jev, and the incident board a non-LLM heuristic baseline.

**Harness.** LLM players run through [mini-SWE-agent](https://github.com/SWE-agent/mini-swe-agent) over
[OpenRouter](https://openrouter.ai) (`openrouter:<model id>`), so every model gets the same agent loop and the same
tools. Each player works through its own command (`casefile` for investigations, `arena` for 1v1) and writes its
answer or policy under `drafts/`.

**Seasons.** Results are reported per season on a fixed seed set. The 2027 season 1 official seeds are **201, 202 and
203** (`task-sets.json`). The `dev` seeds (11, 12) are for development and published examples with answers; an
official set's answer keys are published after its season. A new season is new seeds of the same world.

## Quickstart

Python 3 with `duckdb` and `mini-swe-agent`; `OPENROUTER_API_KEY` set for model players. Building case sets and
playing 1v1 matches also need the Runmere engine (the `runmere` Python package) to simulate the world.

**Alert triage** (decision format, one call per alert):

```bash
python tools/run_decide.py cases/dev-s11 --player openrouter:<model id> --out results/dev-s11-<model>.json
python tools/run_decide.py cases/dev-s11 --player baseline --out results/dev-s11-baseline.json
python tools/leaderboard.py cases/dev-s11 --results mymodel=results/dev-s11-<model>.json baseline=results/dev-s11-baseline.json
```

**Incident investigation** (agentic):

```bash
python run_tasks.py build --split dev --seed 11 --out cases/dev-s11
python run_tasks.py run --task incident --cases cases/dev-s11 --model openrouter:<model id> --trials 3 --out runs/dev-s11-<model>
python run_tasks.py score --runs runs/dev-s11-<model>
python run_tasks.py export-harbor --cases cases/dev-s11 --out harbor/dev-s11    # each case as a Harbor task folder
```

**1v1 defense:**

```bash
python run_fw_match.py --defender openrouter:<model id> --attacker claude:opus --weeks 4 --seed 7 --out runs/match-<model>
python run_fw_series.py --defender openrouter:<model id> --attacker claude:opus --seeds 7,8,9 --out runs/series-<model>
```

`--model baseline` (tasks), `--player baseline` (alert triage) and `--defender baseline:models` (1v1) run the
non-LLM references. `claude:<model>` runs a headless Claude Code session instead of mini-SWE-agent; the official
boards use it only for the 1v1 attacker.

## Repository

```
run_tasks.py           investigation tasks: build case sets, run players, score, leaderboard, publish, Harbor export
run_fw_match.py        one 1v1 match; run_fw_series.py plays a defender over several seeds
tools/run_decide.py    alert triage in the decision format; tools/leaderboard.py builds that board with CIs
arena/tasks/           case building, the casefile tool, monitors, truth, scoring, the decision format
arena/fw/              the 1v1 match: deployment of policies, the arena command, scoring
arena/player.py        the mini-SWE-agent player over OpenRouter
task-sets.json         the seed sets and case counts
docs/tasks.md          the investigation tasks in detail: cases, truth, export, scoring, publishing
```

The world the investigation tasks use is the published Fraud World at its default settings. The 1v1 matches use the
same world with independent fraudsters switched off, so that all fraud is the syndicate's.
